# LG Aimers 7th — Menu Demand Forecasting

**과거 28일 판매 이력으로 영업장·메뉴별 다음 7일 판매량을 예측**하는 시계열 회귀 프로젝트입니다. 모델만 복잡하게 만드는 대신 EDA → 단순 베이스라인 → 시간순 검증 → 오차 분석 → 가설별 실험 → 실제 대회 제출을 반복했습니다.

> **리더보드 (사용자가 제출 후 공유한 결과)** — Public **0.5653057744**, Private **0.5528701672** (SMAPE, 낮을수록 좋음). 이 결과는 `zero_weight=0.25` LightGBM 제출물에 해당합니다. 리더보드 점수와 아래 내부 CV 지표는 계산 조건이 달라 직접 비교할 수 없습니다.

## 1. 문제와 데이터

- 원본 학습 데이터: **102,676행 × 3열**, `영업일자`, `영업장명_메뉴명`, `매출수량`.
- **193개 영업장-메뉴 조합 × 532일**(2023-01-01~2024-06-15). 결측 일자·중복 일자-메뉴 조합 없음.
- 판매량 **0 비율 52.63%**, 음수 14건, 판매량 최대 1,372. 영업장별 영업 패턴, 메뉴별 요일·계절 영향, 간헐적 판매가 공존.
- 테스트는 **TEST_00~TEST_09 각각 독립된 28일 입력**. 각 샘플의 다음 7일을 예측해 총 **70행 × 193개 메뉴**의 제출값을 만듭니다.

## 2. 왜 이런 방법을 골랐나?

| 단계 | 관찰 / 문제 | 가설 및 비교 | 실험에서 확인한 것 / 의사결정 |
|---|---|---|---|
| EDA | 판매 0이 약 절반, 요일·계절에 따라 변동 | 통계적 기준선부터 구축 | 최근 평균, 동일 요일 평균 등 비교 |
| Baseline | 복잡한 모델 없이 예측 가능한가? | 7일 평균(B1), 28일 평균(B0), 전주 동일 요일(B2), 4주 동일 요일(B3) | 11-fold 평균 B1 **0.6974**, B0 **0.7181**. 단일 기준선도 기간에 따라 우열이 바뀜 |
| 첫 ML | 평균만으로 수요 변동을 반영하기 어려움 | Global LightGBM, 과거 28일 요약·요일·월·horizon | 11-fold **0.6567**, B1보다 낮음 |
| 영업장 ID | 같은 영업장 메뉴의 공통 특성을 모델이 놓치는가? | `store_id` 추가 | ML-002 **0.6629**; 개선되지 않아 ID 단독 추가 보류. 영업장 효과 자체가 없다는 뜻은 아님 |
| 영업장별 오류 | 특정 영업장에서 계속 실패한다면 Local 모델? | 9개 영업장별·Fold별 SMAPE | 영업장별 효과가 시점에 따라 뒤집힘. Local 모델 우선 도입 보류 |
| 시점 샘플링 | Weekly 학습 Cutoff가 토요일로 고정 | Weekly / Daily / Rotating | Daily **0.6609**, Weekly **0.6567**(11-fold). 다양한 시작 요일만으로 성능 개선 보장 안 됨. Weekly를 실험 기준으로 유지 |
| Feature Ablation | Gain 중요도가 높은 피처가 실제 검증에도 기여하는가? | `menu_id`, `month`, 요일 피처 각각 제거 | `No_menu_id` **0.6395**, Full **0.6567**; 요일 관련 제거 **0.7334**. ID 없는 모델 후보 채택 |
| Lag 추가 | 동일 요일의 평균은 최근 변화 방향을 잃음 | `lag7`, `lag14` 추가 | **0.6342**, NoID **0.6395**; 9/11 Fold 개선 → 채택 |
| Zero-streak | 연속 미판매 일수가 별도 정보인가? | `zero_streak28` 추가 | **0.6385**로 악화, 제외 |
| 목적함수 | L2/MSE와 실제 SMAPE 불일치 | L1/MAE 비교 | MAE **0.9107** vs MSE **0.6342**. 양수 판매일의 0 근처 예측이 증가 → MSE 유지 |
| 평가 제외 관측치 | 실제 0은 지표에서 제외되는데 학습에서는 동일 비중 | Positive-only vs All MSE | Positive-only **0.5980**(pooled), 하지만 실제 0인 날 과대예측 위험 관찰 |
| 0 가중치 | 0의 정보를 완전히 버리지 않고 비중만 낮추면? | `zero_weight`=1, .5, .25 | CV Store-Macro **0.6418 → 0.6019 → 0.5784**. .25 잠정 후보 |
| 추가 시점 검증 | CV에 맞춘 튜닝일 수 있음 | 2024-06-09~15 시간순 Holdout | Store-Macro **All 0.6058**, **.25 0.6172**. CV 우위가 재현되지 않음. 최종 가중치 최적이라 주장하지 않음 |
| 실제 추론 | 기존 학습 함수는 미래 정답이 필요함 | 미래 정답 불필요한 추론용 피처 생성 | 11개 입력 피처의 학습/추론 값 일치 확인. 10개 TEST 제출 파이프라인 구현 |
| 제출 | 검증한 파이프라인이 대회 형식에서도 동작하는가? | `zero_weight=.25` 제출 | Public **0.5653057744** / Private **0.5528701672** |

**숫자 주의:** 위 표의 CV 수치는 **11개 개발용 Fold의 비가중 Pooled SMAPE 평균**(별도 표시한 Store-Macro와 Holdout 제외)입니다. 같은 Fold를 반복 탐색했으므로 모델 선택 후의 독립 성능 추정치는 아닙니다.

## 3. 최종 제출 설정

- 알고리즘: LightGBM `LGBMRegressor(objective='regression')`.
- 파라미터: `n_estimators=300`, `learning_rate=.05`, `num_leaves=15`, `max_depth=5`, `min_child_samples=50`, `reg_lambda=1.0`, `random_state=42`.
- 모델 입력 11개: `horizon`, `weekday`, `month`, `mean7`, `mean28`, `std7`, `zero_ratio28`, `positive_days28`, `weekday_mean4`, `lag7`, `lag14`.
- `menu_id`와 `store_id`는 **행 식별/정렬에는 사용하되 모델 입력에는 사용하지 않습니다**.
- 주 단위 학습 Cutoff; 과거 28일 피처와 미래 7일 정답으로 지도 학습하며 모든 학습 정답은 해당 검증 Cutoff 이전에만 존재해야 합니다.
- 실제 판매량 0에 `sample_weight=0.25`, 나머지 관측치에 1.0, 음수 예측은 0으로 clip.
- 28일 입력이 들어오면 **정답 없는 추론 피처**를 만들어 7일 예측합니다. 테스트 샘플끼리는 연결하지 않습니다.

## 6. 한계와 후속 작업

1. **평가 지표**: 대회는 실제 판매량 0 제외 및 영업장별 비공개 가중치를 적용합니다. 내부 지표(0 제외 Pooled/동일 영업장 가중 Store-Macro)는 **대리 지표**입니다. 음수 판매 정답 처리도 규칙 및 제출 환경에 맞춰야 합니다.
2. **개발 검증 재사용**: 같은 11개 Fold에서 여러 설계를 비교했으므로 보고된 CV 개선이 독립적으로 확인된 것은 아닙니다. 별도 마지막 7일 Holdout에서는 가중치 .25의 Macro 우위가 깨졌습니다.
3. **목표 함수 차이**: 실제 0의 과대예측은 대회 평가에서 직접 불이익을 받지 않을 수 있습니다. 실제 발주/재고 최적화 모델이라면 판매 발생 확률과 조건부 수량을 분리하는 접근 및 0 포함 지표가 필요합니다.
4. **현재 제출 모델의 범위**: 단일 LightGBM 모델입니다. 공휴일·영업장 집계 피처, 다른 부스팅 모델, 앙상블은 완료된 실험으로 제시하지 않습니다.
5. **실험 재현**: 기존 실험 점수는 사용자가 로컬에서 실행해 공유한 로그를 기반으로 정리했습니다. 이 리포지터리에서 모든 실험을 자동 재수행했다는 뜻이 아닙니다.
